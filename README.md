# Сервис уведомлений

Рассылает уведомления по доменным событиям: слушает RabbitMQ для надёжной
доставки и NATS для эфемерного real-time. Собственной базы не имеет —
состояние живёт в очередях, а адаптеры каналов пишут в журнал.

## Архитектура

Сервис без собственной БД — состояние живёт в очередях, а журнал
доставленных уведомлений хранится в кольцевом буфере в памяти.

Слушает два канала:

| Канал                                   | Тип             | Примеры сообщений                                   |
| ---------------------------------------- | --------------- | ---------------------------------------------------- |
| RabbitMQ (`mirea.events.v1`, durable)    | Надёжные доменные события | `appointment.created`, `appointment.cancelled`, `invoice.issued`, `stock.low` |
| NATS (`mirea.realtime.v1`, pub/sub)      | Эфемерные сообщения       | `mirea.branch.{branch_id}.alerts` (BranchAlert)      |

RabbitMQ-сообщения — с ручным подтверждением и dead-letter очередью, потеря
недопустима. NATS — «выстрелил и забыл»: если подписчик отвалился, он просто
не увидит уведомление, и это нормально, потому что рядом всегда идёт
надёжный дубль через RabbitMQ (например, `stock.low` дублирует
`BranchAlert`).

Единственный синхронный вызов — gRPC-клиент к client-service:

| Куда ходит      | Метод                | Зачем                                          |
| --------------- | --------------------- | ------------------------------------------------ |
| client-service  | `GetClientContacts`  | Получить email/телефон клиента перед отправкой   |

Это и есть та связь, из-за которой client-service и notification-service
выданы в одну пару: контракт этого вызова меняется только внутри вашей
пары, без согласования с другими подгруппами.

## Тесты

`go test ./...` — модульные (обработка событий, форматирование сообщений).
`go test -tags integration ./...` — требует поднятых RabbitMQ и NATS,
проверяет реальную доставку и обработку dead-letter очереди.

## Зависимости

| Модуль | Роль |
|---|---|
| [`mireacrm/contracts-go`](https://github.com/mireacrm/contracts-go) | сообщения и стабы gRPC |
| [`mireacrm/go-common`](https://github.com/mireacrm/go-common) | транспорт, трассировка, метрики, каркас процесса |

Приезжают из сети по версии из `go.mod`. Повышение версии обвяза — ручное
и осознанное: см. [`mireacrm/proto`](https://github.com/mireacrm/proto).

## Локально

```
go test ./...                    # модульные
go test -tags integration ./...  # нужны RabbitMQ и NATS
docker build -t notification-service .
```

Систему целиком поднимает [`mireacrm/deploy`](https://github.com/mireacrm/deploy).
